# Known limitations — 0.9.0-beta.1 candidate

Latest focused evidence is in [UI_UX_COMPLETION_REPORT.md](UI_UX_COMPLETION_REPORT.md). Earlier UI checkpoints remain in [ARCHIVE_REFRESH.md](ARCHIVE_REFRESH.md) and [UI_REFRESH.md](UI_REFRESH.md). [BETA_TEST_REPORT.md](BETA_TEST_REPORT.md) records
the preceding beta checkpoint. These limits remain unless explicitly superseded
by a later scoped result; older checks are historical.

- **NOT MEASURED:** original 20-pairing/50-delivery/20-offline/replay/worker/browser-restart campaigns, exhaustive crash timing, full Doze/reboot/battery-saver/network-switch matrix and current public-network reliability. Focused controlled-relay checks do not establish a failure rate.
- **NOT MEASURED:** current authenticated provider UIs and optional NIP-07/Amber signers. Preview adapters remain preview; see [source matrix](docs/beta/SOURCE_SUPPORT_MATRIX.md).
- **Observed performance limit:** one TCL debug/instrumented 166,939-byte article opened in 1,160 ms including tap waits; six of 390 frames exceeded 100 ms, maximum 303.97 ms. p95 was 9.41 ms. This is a single run, not a release benchmark or leak assessment. The 1,000-document/10,000-highlight corpus was not measured.
- Very large articles use explicit bounded parts of approximately 196,608 canonical UTF-16 units. Selection and narration operate within the current part; dragging across part boundaries and automatic speech continuation are not implemented.
- **NOT MEASURED:** full process-death, tablet/foldable and exhaustive accessibility matrix. Activity recreation, exact native sharing, source deletion, handles/autoscroll and review swipes have scoped physical passes.
- TTS pauses on background and audio-focus loss. Native callbacks/speed/pause were tested; acoustic quality, real calls/headsets and a background media service are not claimed.
- Android background delivery uses OS-scheduled catch-up. Timing depends on the OS/network; a user force-stop requires reopen.
- Export is one-way Markdown/JSONL, not a restorable backup. Pairing keys are excluded. Export import/review-queue restore is not implemented.
- Current candidate acceptance includes TCL T807D and Samsung SM-S918B (S23 Ultra), both Android 16/API 36; see the exact hardening report scope. Historical API-26/other-device checks do not certify these final bytes. 16-KiB update: all 12 bundled `.so` files are ELF 16 KiB-aligned with `./gradlew :app:verify16KbAlignment` gating regressions, and the app installs, launches, and completes a URL capture on the API 36 `google_apis_ps16k` emulator (`PAGESIZE=16384`); no physical 16 KiB device attached. Target/compile SDK remains 34.
- Chrome npm audit reports zero vulnerabilities at the recorded date. Android first scan (OSV batch over the pinned `debugRuntimeClasspath`, 2026-09-10): two findings, both in uncalled code (BouncyCastle GOST/LDAP, Jsoup Cleaner) — closed by upgrading to `bcprov-jdk18on:1.85.2` and `jsoup:1.23.2`, full unit suite green. No copyleft in production dependencies (MIT/Apache-2.0/BSD/Bouncy-Castle). Public relay policies and retention can change.
- NIP-44 has no forward secrecy. Relays can observe routing keys, IP, timing and sizes. Compromised endpoints can access local plaintext and keys. The current native reader renders image descriptions as text without remote image fetches.
- Mac is a reference Swift package; iOS, UniFFI integration and store releases are incomplete. Chrome-to-Android is the implemented product path.
- Automatic inexpensive host checks are enabled for relevant code changes, and run on GitHub when matching source paths change. Consult the workflow run for the pushed commit; local passing tests do not establish a hosted CI pass or store readiness.

- Byte reproducibility: two clean same-path builds (`--offline --no-daemon --max-workers=1 clean`, wrapper-pinned Gradle 8.9) are byte-identical, including a relocated source export — the earlier FAIL compared an incremental artifact against a clean rebuild on an older toolchain. Procedure: `scripts/verify-reproducibility.sh`. Cross-host builds and store-signed release bytes remain unproven.

- URL capture (see [acceptance](CAPTURE_URL_ACCEPTANCE.md)): static extraction only — JavaScript-rendered pages keep an honest link instead of article text; infoboxes are dropped rather than condensed and reference lists are dropped rather than kept as endnotes; password-gated pages report a precise `login_wall` code via form-plus-title signals (never a bypass — always the honest link fallback); plain-http fetches depend on the network carrying port 80 (blocked on the validation carrier, where the request retries durably); extraction improvements land as new document versions, so recaptured URLs can leave an older copy beside the new one until archived/deleted. Spaceless scripts (CJK/Thai) count characters toward article floors and reading time; footnote definitions render as their own un-narrated blocks (pasted-footnote documents re-render slightly, anchors degrade gracefully); RTL gets first-strong paragraph direction with per-paragraph indents still pending.

- Library organization (labels/finishes/stats, Room v13, 2026-09-10): custom labels are facets (autocomplete + union assign), never folders; finishes credit a document once at ≥ 99.9% progress with sticky bookkeeping and credit the full reading-minutes to the device-zone day; the shelf shows totals/week/run with "run" wording only (never "streak") and quiet once-per-threshold milestones at 10/50/100. Header counts, per-tab reading-time estimates, age labels (`3d ago`) and source short names (`wikipedia.org` via a small registrable-domain table — no bundled PSL, so unknown deep hosts keep one extra label rather than risk a wrong cut) are live. Tab order is fixed (2026-09-10 renegotiation, supersedes the earlier hide-empty-tabs contract): the Inbox tab is always visible (count 0 while empty), the chosen tab is never auto-switched away from, and an empty Inbox shows its empty state with actions — while incoming articles still never steal the selected tab. First-save seed: one welcome article, once, only into an empty library. Unit gates: 220/220; lint, both APKs, and 16 KiB alignment green. Device (TCL T807D): 61/82 instrumented green on the normal package; the 21 failures are all environmental — 19 tests self-check for the `.qa` package build, and `HighlightMenuGateInstrumentedTest` fails identically on the pristine tree (UiAutomation `injectInputEvent` refusal). The QA-package run showed the same injection refusals (`UiCompletion`/`ReaderFlow` classes) byte-identically on a pristine HEAD worktree, so they are device-level, not code regressions. Two gesture/measurement tests are load-flaky in full-suite runs and pass in isolation.
- Library search (Room v12): the TCL ships SQLite **without FTS5** ("no such module: FTS5"). Every FTS touchpoint is best-effort behind a capability flag and degrades to LIKE + Umlaut spelling variants + Kotlin-computed snippets with identical row shape and ordering; all 9 `SearchInstrumentedTest` cases pass on the device through the fallback path. GLOB character classes do not match non-ASCII on Android SQLite (desktop parity only), so they are not used. Recents are local-only; search does not read the network.
- S23 Ultra (SM-S918B, Android 16/API 36, 2026-09-10): the final build installs over preserved data and migrates Room v12→v13 in place; the welcome seed fires once for the real package on an empty library and is suppressed in the `.qa` package (destructive fixtures need a controllable library). QA-class runs on this device (21 tests): 17 green; the four remaining failures — two shuffle-order waits, the snackbar "Dismiss" action, a batch-move notice and one table-column alignment — flap identically on a pristine HEAD build (reproduced on a pristine worktree twice), i.e. injected-tap timing and variable-font load races, not product regressions. Note the test device runs German locale: Compose's platform snackbar dismiss label is localized, so any QA expectation of the literal "Dismiss" only holds on English-locale devices. During USB test runs keep the screen awake (`svc power stayon usb` plus one manual unlock) — a PIN re-lock mid-suite presents as blanket "Timed out: <control>" failures.
