DEFECT CLOSED
- Completed Chrome state retained the Android channel, protocol version,
  relays, and relay digest but not the public identity derived from the exact
  Chrome device secret that completed pairing.
- A missing/malformed secret could leave a false connected UI. A replacement
  valid secret could sign under stale Android trust. A never-sent capture made
  before identity repair could also retain the wrong sender public key.

CONTROLS
- Completed state now persists the authenticated Chrome device public key.
- Paired-state reads require a valid private scalar, its exact derived public
  binding, a valid Android x-only channel point, protocol v2, the canonical
  six-default-plus-custom relay set, and its exact digest.
- Compatible earlier-v2 state receives a public binding marker only when its
  existing private key is valid. Missing, malformed, or mismatched state fails
  closed and removes only the unusable channel binding; preferences, device
  identity where still valid, and durable captures remain local.
- In-flight sessions are cancelled and stripped of their one-time key if the
  current device identity no longer matches their request.
- A never-sent unbound capture can adopt the repaired identity before its
  manifest ID is computed. An already-bound sender mismatch is retained as a
  local failure before network use.
